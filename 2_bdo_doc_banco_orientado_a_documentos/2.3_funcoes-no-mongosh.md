# 2.3 Funções no `mongosh`: da organização à validação de regras

Este material apresenta o uso de funções JavaScript diretamente no `mongosh`, incluindo o shell embutido no MongoDB Compass.

A proposta é construir uma evolução lógica: começar com funções simples, passar por funções com parâmetros e retorno, consultar dados no MongoDB, validar regras e, por fim, organizar uma rotina maior de criação de pedidos.

Neste material, não usaremos arquivos `.js` externos. Todos os exemplos podem ser copiados e executados diretamente no shell do Compass.

---

## 1. O que é uma função?

Uma função é um bloco de código com um nome. Ela pode ser chamada várias vezes para executar uma tarefa.

Exemplo simples:

```javascript
function mostrarMensagem() {
  print("Banco de Dados Não Relacional")
}

mostrarMensagem()
```

Neste exemplo:

- `function` cria uma função;
- `mostrarMensagem` é o nome da função;
- o bloco entre `{ }` contém os comandos executados;
- `mostrarMensagem()` chama a função.

---

## 2. Funções no shell do MongoDB Compass

No Compass, é possível abrir o shell embutido e executar comandos JavaScript.

Exemplo:

```javascript
use aula2_funcoes
```

Depois, é possível criar uma função:

```javascript
function olaAluno(nome) {
  print("Olá, " + nome)
}

olaAluno("Ana")
```

A função fica disponível enquanto a sessão do shell estiver aberta.

Se o shell for fechado ou reiniciado, a função precisará ser criada novamente.

---

## 3. Funções com parâmetros

Parâmetros são valores recebidos pela função.

```javascript
function somar(a, b) {
  return a + b
}

somar(10, 5)
```

Resultado esperado:

```javascript
15
```

Outro exemplo:

```javascript
function calcularTotal(quantidade, precoUnitario) {
  return quantidade * precoUnitario
}

calcularTotal(3, 50)
```

Resultado esperado:

```javascript
150
```

---

## 4. Funções com retorno

O comando `return` devolve um valor para quem chamou a função.

```javascript
function produtoEstaCaro(preco) {
  return preco > 100
}

produtoEstaCaro(150)
```

Resultado esperado:

```javascript
true
```

Teste também:

```javascript
produtoEstaCaro(80)
```

Resultado esperado:

```javascript
false
```

---

## 5. Funções com decisão

Funções podem usar `if` para tomar decisões.

```javascript
function classificarEstoque(quantidade) {
  if (quantidade === 0) {
    return "sem estoque"
  }

  if (quantidade < 10) {
    return "estoque baixo"
  }

  return "estoque adequado"
}

classificarEstoque(0)
classificarEstoque(5)
classificarEstoque(30)
```

Essa função já começa a representar uma regra de negócio.

## 7. Função que consulta o banco

Agora a função passa a consultar uma coleção.

```javascript
function buscarClientePorEmail(email) {
  return db.clientes.findOne({ email: email })
}

buscarClientePorEmail("ana@email.com")
```

Esse tipo de função organiza uma consulta que pode ser reutilizada.

## 8. Função para validar cliente ativo

A função abaixo verifica se um cliente existe e está ativo.

```javascript
function clienteEstaAtivo(clienteId) {
  const cliente = db.clientes.findOne({
    _id: clienteId,
    ativo: true
  })

  return cliente !== null
}
```

Teste com cliente ativo:

```javascript
clienteEstaAtivo(ObjectId("650000000000000000000301"))
```

Teste com cliente inativo:

```javascript
clienteEstaAtivo(ObjectId("650000000000000000000302"))
```

Essa função transforma uma consulta em uma regra reutilizável.

## 10. Função para validar estoque

```javascript
function produtoTemEstoque(produtoId, quantidade) {
  const produto = db.produtos.findOne({
    _id: produtoId,
    ativo: true,
    estoque: { $gte: quantidade }
  })

  return produto !== null
}
```

Teste com produto disponível:

```javascript
produtoTemEstoque(ObjectId("650000000000000000000401"), 2)
```

Teste com produto sem estoque:

```javascript
produtoTemEstoque(ObjectId("650000000000000000000402"), 1)
```

Essa função valida três condições:

- o produto existe;
- o produto está ativo;
- o estoque é suficiente.

## 11. Função para registrar logs

Uma função também pode inserir documentos em uma coleção auxiliar.

```javascript
function registrarLog(acao, detalhe) {
  db.logs.insertOne({
    acao: acao,
    detalhe: detalhe,
    data: new Date()
  })
}
```

Exemplo de uso:

```javascript
registrarLog("teste", "Primeiro log criado pela função")
```

Consultando os logs:

```javascript
db.logs.find().pretty()
```

Importante: isso não é uma trigger. O log só é criado porque a função foi chamada explicitamente.

## 12. Função para baixar estoque

Agora vamos criar uma função que consulta e atualiza dados.

```javascript
function baixarEstoque(produtoId, quantidade) {
  if (quantidade <= 0) {
    print("Quantidade inválida.")
    return false
  }

  const resultado = db.produtos.updateOne(
    {
      _id: produtoId,
      ativo: true,
      estoque: { $gte: quantidade }
    },
    {
      $inc: { estoque: -quantidade }
    }
  )

  return resultado.modifiedCount === 1
}
```

Teste:

```javascript
baixarEstoque(ObjectId("650000000000000000000401"), 2)
```

Verifique o estoque:

```javascript
db.produtos.find(
  { _id: ObjectId("650000000000000000000401") },
  { _id: 0, nome: 1, estoque: 1 }
)
```

## 13. Evoluindo para uma rotina maior

Agora vamos combinar funções em uma rotina mais próxima de um caso real.

A função `criarPedido` deve:

1. verificar se o cliente está ativo;
2. verificar se há itens no pedido;
3. validar quantidade;
4. verificar produto e estoque;
5. calcular valor total;
6. inserir o pedido;
7. baixar estoque;
8. registrar log.

```javascript
function criarPedido(clienteId, itens) {
  if (!clienteEstaAtivo(clienteId)) {
    print("Cliente inexistente ou inativo.")
    registrarLog("pedido_recusado", "Cliente inválido: " + clienteId)
    return
  }

  if (!Array.isArray(itens) || itens.length === 0) {
    print("O pedido precisa ter pelo menos um item.")
    registrarLog("pedido_recusado", "Pedido sem itens")
    return
  }

  let valorTotal = 0
  const itensPedido = []

  for (const item of itens) {
    if (item.quantidade <= 0) {
      print("Quantidade inválida.")
      registrarLog("pedido_recusado", "Quantidade inválida")
      return
    }

    const produto = db.produtos.findOne({
      _id: item.produtoId,
      ativo: true,
      estoque: { $gte: item.quantidade }
    })

    if (!produto) {
      print("Produto inválido ou estoque insuficiente: " + item.produtoId)
      registrarLog("pedido_recusado", "Produto inválido ou estoque insuficiente")
      return
    }

    valorTotal += produto.preco * item.quantidade

    itensPedido.push({
      produtoId: produto._id,
      nome: produto.nome,
      quantidade: item.quantidade,
      precoUnitario: produto.preco
    })
  }

  const resultado = db.pedidos.insertOne({
    clienteId: clienteId,
    data: new Date(),
    status: "finalizado",
    itens: itensPedido,
    valorTotal: valorTotal
  })

  for (const item of itensPedido) {
    db.produtos.updateOne(
      { _id: item.produtoId },
      { $inc: { estoque: -item.quantidade } }
    )
  }

  registrarLog("pedido_criado", "Pedido criado: " + resultado.insertedId)
  print("Pedido criado com sucesso.")
}
```

## 16. Essas funções são procedures?

Elas se parecem com procedures em alguns aspectos, mas não são stored procedures tradicionais.

Em bancos relacionais, uma procedure normalmente fica armazenada no banco, é gerenciada pelo SGBD e pode ser chamada como parte da lógica do banco.

As funções deste material:

- são escritas em JavaScript;
- são executadas no `mongosh`;
- ficam disponíveis apenas na sessão atual;
- ajudam a organizar uma rotina;
- simulam uma lógica parecida com procedure;
- não ficam salvas automaticamente como objeto permanente do banco.

Resumo:

> Funções no `mongosh` são uma boa ponte didática para entender procedures, mas não são procedures tradicionais.

---

## 17. Essas funções são triggers?

Não.

Uma trigger é executada automaticamente quando ocorre um evento, como inserção, alteração ou remoção.

As funções deste material só executam quando são chamadas manualmente.

Exemplo:

```javascript
registrarLog("consulta", "Consulta feita pelo aluno")
```

O log só é criado porque chamamos a função. Se ninguém chamar a função, nada acontece automaticamente.

Resumo:

> Funções no `mongosh` podem simular automações, mas não são triggers.

---

## 18. E o `system.js`?

O MongoDB possui uma coleção especial chamada `system.js`, que permite armazenar funções JavaScript no banco.

Exemplo conceitual:

```javascript
db.system.js.save({
  _id: "calcularTotal",
  value: function (quantidade, preco) {
    return quantidade * preco
  }
})
```

Depois, seria possível carregar essas funções com:

```javascript
db.loadServerScripts()
```

Apesar disso, essa abordagem não será usada nesta disciplina como prática principal.

Motivos:

- JavaScript server-side está depreciado em versões recentes do MongoDB;
- não representa a prática mais comum em projetos novos;
- pode criar confusão com stored procedures relacionais;
- regras de negócio geralmente ficam na aplicação ou em serviços próprios.

Para fins didáticos, é suficiente entender que esse recurso existe, mas que não é o caminho recomendado para a disciplina.

---

## 19. Limites dessa abordagem

Funções no `mongosh` são úteis para estudo, testes e scripts simples, mas possuem limites:

- desaparecem ao fechar a sessão do shell;
- precisam ser recriadas se o shell for reiniciado;
- não são disparadas automaticamente;
- não substituem a camada de aplicação;
- não substituem validações de schema;
- não resolvem sozinhas problemas de concorrência;
- podem ficar difíceis de manter se crescerem demais.

Em sistemas reais, regras de negócio costumam ficar na aplicação, em serviços, em validações de schema, em transações ou em recursos da plataforma, dependendo do caso.
