# 2.3 Exemplos práticos: integridade e automação

Este material apresenta exemplos práticos de como simular regras de integridade e automação em um banco orientado a documentos.

Em bancos NoSQL, algumas validações que seriam tratadas por chaves estrangeiras, restrições rígidas ou relacionamentos tradicionais podem precisar ser controladas pela aplicação, por scripts ou por recursos específicos do banco.

---

## 1. Cenário inicial

Vamos considerar um sistema simples com clientes, produtos e pedidos.

```javascript
use loja
```

Cadastro de clientes:

```javascript
db.clientes.insertMany([
  {
    _id: ObjectId("650000000000000000000101"),
    nome: "Ana Souza",
    email: "ana@email.com",
    ativo: true
  },
  {
    _id: ObjectId("650000000000000000000102"),
    nome: "Bruno Lima",
    email: "bruno@email.com",
    ativo: false
  }
])
```

Cadastro de produtos:

```javascript
db.produtos.insertMany([
  {
    _id: ObjectId("650000000000000000000201"),
    nome: "Teclado",
    preco: 120.00,
    estoque: 10,
    ativo: true
  },
  {
    _id: ObjectId("650000000000000000000202"),
    nome: "Mouse",
    preco: 60.00,
    estoque: 3,
    ativo: true
  }
])
```

## 2. Validação manual antes de inserir pedido

Antes de cadastrar um pedido, podemos verificar se o cliente existe e está ativo.

```javascript
const cliente = db.clientes.findOne({
  _id: ObjectId("650000000000000000000101"),
  ativo: true
})

if (cliente) {
  db.pedidos.insertOne({
    clienteId: cliente._id,
    data: new Date(),
    status: "aberto",
    itens: [],
    valorTotal: 0
  })
} else {
  print("Cliente inexistente ou inativo.")
}
```

Essa validação evita que um pedido seja criado para um cliente inválido.

---

## 3. Validação de estoque

Antes de adicionar um item ao pedido, podemos verificar se o produto existe, está ativo e possui estoque suficiente.

```javascript
const produto = db.produtos.findOne({
  _id: ObjectId("650000000000000000000201"),
  ativo: true,
  estoque: { $gte: 2 }
})

if (produto) {
  print("Produto disponível para venda.")
} else {
  print("Produto indisponível ou estoque insuficiente.")
}
```

---

## 4. Atualização automática de estoque

Depois de confirmar uma venda, o estoque pode ser reduzido com `$inc`.

```javascript
db.produtos.updateOne(
  {
    _id: ObjectId("650000000000000000000201"),
    estoque: { $gte: 2 }
  },
  {
    $inc: { estoque: -2 }
  }
)
```

Essa operação reduz o estoque apenas se ainda houver quantidade suficiente.

---

## 5. Inserindo pedido com itens

```javascript
db.pedidos.insertOne({
  clienteId: ObjectId("650000000000000000000101"),
  data: new Date(),
  status: "finalizado",
  itens: [
    {
      produtoId: ObjectId("650000000000000000000201"),
      nome: "Teclado",
      quantidade: 2,
      precoUnitario: 120.00
    }
  ],
  valorTotal: 240.00
})
```

Neste exemplo, alguns dados do produto foram copiados para dentro do pedido. Isso preserva o histórico da venda mesmo que o preço do produto mude depois.

## 6. Criando uma função auxiliar no `mongosh`

Podemos criar uma função para concentrar a regra de criação de pedidos.

```javascript
function criarPedido(clienteId, itens) {
  const cliente = db.clientes.findOne({
    _id: clienteId,
    ativo: true
  })

  if (!cliente) {
    print("Cliente inexistente ou inativo.")
    return
  }

  let valorTotal = 0
  const itensPedido = []

  for (const item of itens) {
    const produto = db.produtos.findOne({
      _id: item.produtoId,
      ativo: true,
      estoque: { $gte: item.quantidade }
    })

    if (!produto) {
      print("Produto inválido ou estoque insuficiente: " + item.produtoId)
      return
    }

    valorTotal += produto.preco * item.quantidade

    itensPedido.push({
      produtoId: produto._id,
      nome: produto.nome,
      quantidade: item.quantidade,
      precoUnitario: produto.preco
    })
  }

  db.pedidos.insertOne({
    clienteId: cliente._id,
    data: new Date(),
    status: "finalizado",
    itens: itensPedido,
    valorTotal: valorTotal
  })

  for (const item of itensPedido) {
    db.produtos.updateOne(
      { _id: item.produtoId },
      { $inc: { estoque: -item.quantidade } }
    )
  }

  print("Pedido criado com sucesso.")
}
```

Exemplo de uso:

```javascript
criarPedido(
  ObjectId("650000000000000000000101"),
  [
    {
      produtoId: ObjectId("650000000000000000000201"),
      quantidade: 1
    }
  ]
)
```

## 7. Consultas de conferência

Verificar pedidos cadastrados:

```javascript
db.pedidos.find().pretty()
```

Verificar estoque dos produtos:

```javascript
db.produtos.find({}, { nome: 1, estoque: 1, _id: 0 })
```

Verificar pedidos de um cliente:

```javascript
db.pedidos.find({
  clienteId: ObjectId("650000000000000000000101")
})
```

## 8. Exercícios

1. Adapte a função `criarPedido` para impedir pedidos com quantidade menor ou igual a zero.
2. Crie uma regra para impedir pedidos sem itens.
3. Adicione um campo `cancelado` nos pedidos e simule o cancelamento de uma venda.
4. Ao cancelar um pedido, devolva a quantidade dos produtos ao estoque.
5. Crie uma consulta que liste o total vendido por produto.

## 9. Discussão

Após executar os exemplos, reflita:

- quais regras ficaram sob responsabilidade da aplicação ou do script?
- quais problemas poderiam ocorrer se duas vendas fossem feitas ao mesmo tempo?
- que dados foram copiados para preservar histórico?
- que dados ficaram referenciados para evitar duplicação excessiva?
- em quais situações faria sentido usar transações?
