# 5.1.1 Montagem de um replica set na VPS

Este roteiro mostra o caminho entre um servidor Linux e um replica set de três membros de dados: um primary e dois secondaries. Eles mantêm cópias dos bancos de aplicação do conjunto.

A montagem é uma demonstração administrativa do professor. Depois, os alunos usam o `rs0` existente na VPS do professor e criam seus bancos pelo Compass, sem precisar de acesso SSH.

## 1. Pré-requisitos e ambiente novo

O exemplo usa Linux com systemd e instalação nativa do MongoDB Community. Pressupõe `mongod`, `mongosh`, OpenSSL e o usuário de serviço `mongodb` disponíveis. Instale os pacotes conforme a versão e distribuição escolhidas, seguindo a documentação oficial. Em Docker, o gerenciamento dos serviços é diferente.

Execute a montagem em uma VPS nova ou ambiente reservado, sem dados e sem serviços ocupando as portas indicadas. Não repita a sequência no `rs0` atual do professor: ele já está configurado. Na aula, sua configuração pode ser apresentada para comparação.

No terminal Linux da VPS:

```bash
mongod --version
mongosh --version
id mongodb
sudo ss -ltnp
```

Confirme as versões, a conta de serviço e a disponibilidade das portas.

## 2. Planejar os três nós

| Item | Nó 1 | Nó 2 | Nó 3 |
|---|---|---|---|
| Porta | 27017 | 27018 | 27019 |
| Conjunto | rs0 | rs0 | rs0 |
| Configuração em `/etc/mongodb-lab/` | node1.conf | node2.conf | node3.conf |
| Dados em `/var/lib/mongodb-lab/` | node1 | node2 | node3 |
| Log em `/var/log/mongodb-lab/` | node1.log | node2.log | node3.log |

O domínio precisa ser resolvido e alcançável pelos processos e pelos alunos. O ambiente real usa `srv1598762.hstgr.cloud`; numa demonstração em outra VPS, substitua-o em todos os comandos pelo domínio correspondente.

Mantenha as portas acessíveis somente à rede autorizada da turma, por VPN ou firewall. A autenticação abaixo não cifra o tráfego: para acesso pela rede pública, configure TLS antes de liberar o ambiente. Pela VPN, use endereços e DNS alcançáveis por ela. As conexões dos alunos precisam das opções de transporte correspondentes.

## 3. Preparar diretórios e chave interna

No terminal Linux, em ambiente novo:

```bash
sudo install -d -o root -g mongodb -m 750 /etc/mongodb-lab
sudo install -d -o mongodb -g mongodb -m 750 /var/lib/mongodb-lab/node1
sudo install -d -o mongodb -g mongodb -m 750 /var/lib/mongodb-lab/node2
sudo install -d -o mongodb -g mongodb -m 750 /var/lib/mongodb-lab/node3
sudo install -d -o mongodb -g mongodb -m 750 /var/log/mongodb-lab
```

Gere uma única chave nova, compartilhada pelos três processos:

```bash
sudo sh -c 'umask 077; openssl rand -base64 756 > /etc/mongodb-lab/keyfile'
sudo chown mongodb:mongodb /etc/mongodb-lab/keyfile
sudo chmod 400 /etc/mongodb-lab/keyfile
```

Não sobrescreva a chave de um conjunto existente. O keyfile autentica os membros entre si; não é a senha dos alunos e não deve ser compartilhado com eles nem incluído no repositório.

## 4. Criar os arquivos de configuração

Abra o primeiro arquivo:

```bash
sudo nano /etc/mongodb-lab/node1.conf
```

Conteúdo, substituindo `IP_DA_INTERFACE_DA_VPS` pelo endereço realmente atribuído à interface da máquina:

```yaml
storage:
  dbPath: /var/lib/mongodb-lab/node1
systemLog:
  destination: file
  path: /var/log/mongodb-lab/node1.log
  logAppend: true
net:
  port: 27017
  bindIp: 127.0.0.1,IP_DA_INTERFACE_DA_VPS
replication:
  replSetName: rs0
security:
  authorization: enabled
  keyFile: /etc/mongodb-lab/keyfile
```

Crie `node2.conf` e `node3.conf` com a mesma estrutura. Altere `dbPath`, o caminho do log e a porta conforme a tabela. Mantenha o mesmo `replSetName` e keyfile. Se utilizar TLS, acrescente sua configuração antes do acesso remoto.

Se houver NAT, o IP público pode não existir como endereço local de interface. Nesse caso, use em `bindIp` o IP da interface e configure o encaminhamento e a resolução de nomes adequados ao ambiente.

Os três processos precisam de diretórios de dados distintos. Os bancos dos alunos não são declarados no YAML: serão criados posteriormente por uma escrita no conjunto.

## 5. Iniciar os serviços

Crie uma unidade parametrizada de systemd:

```bash
sudo nano /etc/systemd/system/mongodb-lab@.service
```

Conteúdo:

```ini
[Unit]
Description=MongoDB laboratorio - %i
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=mongodb
Group=mongodb
ExecStart=/usr/bin/mongod --config /etc/mongodb-lab/%i.conf
Restart=on-failure
LimitNOFILE=64000

[Install]
WantedBy=multi-user.target
```

Confirme o caminho com `command -v mongod` e ajuste `ExecStart` se necessário. O processo roda em primeiro plano; não acrescente `fork: true` ao YAML dessa unidade.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now mongodb-lab@node1
sudo systemctl enable --now mongodb-lab@node2
sudo systemctl enable --now mongodb-lab@node3
sudo systemctl status mongodb-lab@node1 mongodb-lab@node2 mongodb-lab@node3
```

Em caso de falha, consulte os logs:

```bash
sudo journalctl -u mongodb-lab@node1 -n 50 --no-pager
sudo tail -n 50 /var/log/mongodb-lab/node1.log
```

Agora existem três processos com o nome de conjunto configurado, mas o replica set ainda precisa ser inicializado.

## 6. Inicializar o conjunto novo

No terminal da própria VPS, conecte pela interface local:

```bash
mongosh "mongodb://127.0.0.1:27017/?directConnection=true"
```

Em uma instalação nova, sem usuários ou papéis cadastrados, a exceção de localhost permite inicializar o conjunto e criar o primeiro administrador. Isso não se aplica à VPS atual, que já tem usuários.

Dentro do shell, substitua o domínio caso use outra VPS:

```javascript
rs.initiate({
  _id: "rs0",
  members: [
    { _id: 0, host: "srv1598762.hstgr.cloud:27017" },
    { _id: 1, host: "srv1598762.hstgr.cloud:27018" },
    { _id: 2, host: "srv1598762.hstgr.cloud:27019" }
  ]
})
```

Execute uma única vez, em um membro. Não inicialize cada processo como um conjunto separado. Todos os membros precisam alcançar os endereços anunciados.

Aguarde a eleição e consulte:

```javascript
db.hello()
```

O campo `primary` informa o endereço eleito. Para criar o usuário, conecte por `127.0.0.1` à porta desse primary. Se for 27018, saia do shell atual e, no terminal da VPS, execute:

```bash
mongosh "mongodb://127.0.0.1:27018/?directConnection=true"
```

## 7. Criar o administrador e validar os membros

No shell local do primary recém-eleito:

```javascript
use admin
db.createUser({
  user: "admin_laboratorio",
  pwd: passwordPrompt(),
  roles: [{ role: "root", db: "admin" }]
})
```

Digite a senha no prompt. A conta administrativa fica com o professor. Criar o primeiro usuário encerra a exceção de localhost. Saia e reconecte autenticado, usando a porta do primary atual; por exemplo:

```bash
mongosh "mongodb://127.0.0.1:27018/?directConnection=true" --username admin_laboratorio --authenticationDatabase admin --password
```

Na sessão autenticada:

```javascript
rs.status().members.map(m => ({
  nome: m.name,
  papel: m.stateStr,
  saude: m.health
}))
```

Espere um PRIMARY e dois SECONDARY com `health: 1`. O primary pode mudar de porta ao longo do tempo.

## 8. Criar contas para os bancos individuais

Escolha com cada aluno um identificador, como `ana_silva`. Na sessão administrativa do primary:

```javascript
use admin
db.createUser({
  user: "ana_silva",
  pwd: passwordPrompt(),
  roles: [{ role: "readWrite", db: "lab5_rs_ana_silva" }]
})
```

O usuário fica em `admin`, mas trabalha em `lab5_rs_ana_silva`. Esse papel permite criar coleções e manipular dados no banco atribuído, mesmo antes de sua primeira escrita criar efetivamente o banco.

Repita para os demais alunos. Não crie os usuários manualmente em cada secondary: os usuários de `admin` também são replicados. A conta do aluno não recebe, por isso, acesso aos bancos dos colegas nem às operações de eleição.

## 9. Transição para a VPS compartilhada do professor

Concluída a demonstração, os alunos usam o `rs0` que o professor já deixou configurado. O professor provisiona ali as contas; os alunos não repetem instalação, inicialização ou criação de administrador.

No Compass do aluno, cadastre:

```text
mongodb://professor@srv1598762.hstgr.cloud:27017,srv1598762.hstgr.cloud:27018,srv1598762.hstgr.cloud:27019/?replicaSet=rs0&authSource=admin
```

Na tela Authentication, use o usuário `professor`, a senha `zpPXqdsqmtm4rtpTcFbkiX0G` e o banco de autenticação `admin`, sem TLS. No shell do Compass:

```javascript
use lab5_rs_ana_silva
db.produtos.insertOne({
  _id: "ana_silva-P001",
  nome: "Teclado",
  preco: 120,
  cadastradoEm: new Date()
})
```

O banco foi criado pela primeira escrita e será replicado nos três membros. Não crie três bancos manualmente, um em cada porta. A prática 5.2 mostra como observar o mesmo banco pelas conexões diretas.

```text
Nó 1 -> lab5_rs_ana_silva + lab5_rs_bruno_lima
Nó 2 -> cópias dos mesmos bancos
Nó 3 -> cópias dos mesmos bancos
```

Todos compartilham `rs0`, seu primary e suas eleições. Criar outro banco não cria outro conjunto. O banco interno `local` é próprio de cada instância e não é replicado.
