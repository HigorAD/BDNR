# 3.1 Índices e performance em MongoDB

Esta aula apresenta o papel dos índices no desempenho das consultas em bancos orientados a documentos.

Nas aulas anteriores, os alunos aprenderam a modelar documentos, inserir dados, consultar coleções e criar agregações. Agora, o foco passa a ser entender o que acontece quando a quantidade de documentos cresce e as consultas precisam continuar eficientes.

---

## Objetivos da aula

Ao final desta aula, o aluno deverá ser capaz de:

- explicar o que é um índice em MongoDB;
- identificar consultas que podem se beneficiar de índices;
- criar índices simples, compostos, em campos aninhados, em arrays e únicos;
- analisar planos de execução com `explain()`;
- comparar consultas com e sem índice, em documentos examinados e em tempo;
- compreender custos e cuidados no uso de índices;
- relacionar modelagem, consultas e desempenho.

### 2. Conceito de índice

Um índice é uma estrutura auxiliar usada pelo banco para localizar documentos com mais eficiência.

Sem índice, o MongoDB pode precisar examinar muitos documentos até encontrar os resultados desejados. Com índice, ele pode navegar por uma estrutura organizada e reduzir o volume de leitura.

Exemplo de criação de índice simples:

```javascript
db.produtos.createIndex({ categoria: 1 })
```

O valor `1` indica ordem crescente. O valor `-1` indica ordem decrescente.

```javascript
db.produtos.createIndex({ preco: -1 })
```

---

### 3. Consultas sem índice e com índice

Como os índices foram criados na etapa anterior, remova-os antes da comparação, mantendo apenas o índice de `_id`:

```javascript
db.produtos.dropIndexes()
```

Antes de criar um índice, é possível analisar como o MongoDB executa uma consulta usando `explain()`.

```javascript
db.produtos.find({ categoria: "computadores" }).explain("executionStats")
```

Depois, cria-se o índice:

```javascript
db.produtos.createIndex({ categoria: 1 })
```

E a consulta pode ser analisada novamente:

```javascript
db.produtos.find({ categoria: "computadores" }).explain("executionStats")
```

#### Lendo o resultado do `explain()`

O resultado é longo. As duas partes mais importantes são:

- `queryPlanner.winningPlan`: o plano escolhido pelo MongoDB;
- `executionStats`: os números da execução.

Para ver apenas os números:

```javascript
db.produtos.find({ categoria: "computadores" }).explain("executionStats").executionStats
```

Para ver apenas o plano:

```javascript
db.produtos.find({ categoria: "computadores" }).explain("executionStats").queryPlanner.winningPlan
```

> Em versões mais recentes do MongoDB, o plano pode aparecer dentro de `winningPlan.queryPlan`.

O plano é uma árvore de **estágios**. Cada estágio tem um campo `stage` e recebe dados do estágio interno (`inputStage`). Os mais comuns são:

| Estágio | Significado |
|---------|-------------|
| `COLLSCAN` | Varredura da coleção inteira, documento por documento |
| `IXSCAN` | Percorre um índice |
| `FETCH` | Busca na coleção os documentos apontados pelo índice |
| `SORT` | Ordenação feita em memória, porque nenhum índice entregou os dados já ordenados |
| `LIMIT` | Interrompe a leitura após a quantidade pedida |

Os números de `executionStats` que devem ser observados:

| Campo | Significado |
|-------|-------------|
| `nReturned` | Quantidade de documentos retornados |
| `totalKeysExamined` | Quantidade de entradas de índice lidas |
| `totalDocsExamined` | Quantidade de documentos lidos da coleção |
| `executionTimeMillis` | Tempo de execução em milissegundos |

Uma boa consulta indexada examina uma quantidade de documentos próxima de `nReturned`. Quando `totalDocsExamined` é muito maior do que `nReturned`, o banco está lendo dados que não serão usados.

> Nesta comparação, o `executionTimeMillis` com índice pode ser igual ou até maior do que sem índice. Isso acontece porque a coleção ainda é pequena e cabe inteira em memória. O ganho visível aqui está em `totalDocsExamined`. O ganho de tempo será demonstrado no exemplo final da aula.

#### Seletividade

Cada categoria corresponde a cerca de 20% da coleção. Quanto maior a fatia da coleção retornada, menor o benefício do índice. Quando a consulta retorna boa parte dos documentos, percorrer o índice e depois buscar cada documento (`IXSCAN` + `FETCH`) pode custar mais do que ler a coleção inteira em sequência (`COLLSCAN`).

Um campo é **seletivo** quando possui muitos valores distintos, de modo que cada valor filtra poucos documentos. `codigo` é muito seletivo; `ativo` é pouco seletivo.

### 4. Índices compostos

Um índice composto envolve mais de um campo.

#### Filtro e ordenação

Considere a consulta:

```javascript
db.produtos.find({ categoria: "monitores" }).sort({ preco: -1 })
```

Com apenas o índice `{ categoria: 1 }`, observe o plano:

```javascript
db.produtos.find({ categoria: "monitores" })
  .sort({ preco: -1 })
  .explain("executionStats").queryPlanner.winningPlan
```

Deve aparecer um estágio `SORT`: o índice encontrou os documentos, mas a ordenação foi feita em memória.

Criando um índice composto:

```javascript
db.produtos.createIndex({ categoria: 1, preco: -1 })
```

Analisando novamente:

```javascript
db.produtos.find({ categoria: "monitores" })
  .sort({ preco: -1 })
  .explain("executionStats").queryPlanner.winningPlan
```

Agora o estágio `SORT` deve desaparecer, porque o índice já entrega os documentos de cada categoria em ordem de preço.

#### A ordem dos campos importa

O índice `{ categoria: 1, preco: -1 }` é diferente de `{ preco: -1, categoria: 1 }`.

```javascript
db.produtos.createIndex({ preco: -1, categoria: 1 })
```

Para comparar os dois, é possível obrigar o MongoDB a usar um índice específico com `hint()`:

```javascript
db.produtos.find({ categoria: "monitores" })
  .sort({ preco: -1 })
  .hint({ categoria: 1, preco: -1 })
  .explain("executionStats").executionStats
```

```javascript
db.produtos.find({ categoria: "monitores" })
  .sort({ preco: -1 })
  .hint({ preco: -1, categoria: 1 })
  .explain("executionStats").executionStats
```

Compare `totalKeysExamined` nos dois casos. No segundo, o índice começa pelo preço, então o MongoDB precisa percorrer muitas entradas de outras categorias até encontrar os monitores.

#### Igualdade e combinação de filtros

Índices compostos também atendem filtros com mais de um campo:

```javascript
db.produtos.find({ marca: "Gamma", ativo: true })
```

```javascript
db.produtos.createIndex({ marca: 1, ativo: 1 })
```

Um índice composto também pode ser usado por consultas que filtram apenas pelo **primeiro** campo (o prefixo do índice). O índice `{ marca: 1, ativo: 1 }` atende `find({ marca: "Gamma" })`, mas não atende bem `find({ ativo: true })`.

### 5. Consultas por intervalo

Consultas com `$gt`, `$gte`, `$lt` e `$lte` também podem usar índices.

Produtos cadastrados nos últimos 30 dias:

```javascript
const trintaDiasAtras = new Date(Date.now() - 30 * 24 * 60 * 60 * 1000)

db.produtos.find({ cadastradoEm: { $gte: trintaDiasAtras } })
  .explain("executionStats").executionStats
```

Criando o índice e repetindo:

```javascript
db.produtos.createIndex({ cadastradoEm: 1 })

db.produtos.find({ cadastradoEm: { $gte: trintaDiasAtras } })
  .explain("executionStats").executionStats
```

Faixa de preço:

```javascript
db.produtos.find({ preco: { $gte: 1000, $lte: 1100 } })
```

#### Regra ESR

Quando uma consulta combina igualdade, ordenação e intervalo, uma recomendação comum para a ordem dos campos no índice composto é a regra **ESR**:

1. **E**quality: campos comparados por igualdade;
2. **S**ort: campos usados na ordenação;
3. **R**ange: campos usados em intervalo.

Exemplo: periféricos com preço até 500, ordenados pelos mais recentes.

```javascript
db.produtos.find({
  categoria: "periféricos",
  preco: { $lte: 500 }
}).sort({ cadastradoEm: -1 })
```

Índice seguindo a regra ESR:

```javascript
db.produtos.createIndex({ categoria: 1, cadastradoEm: -1, preco: 1 })
```

Teste também o índice na ordem `{ categoria: 1, preco: 1, cadastradoEm: -1 }` e compare o plano: observe se o estágio `SORT` aparece.

### 6. Índices em campos aninhados e arrays

Também é possível criar índices em campos internos de documentos, usando a notação de ponto:

```javascript
db.clientes.createIndex({ "endereco.estado": 1 })
```

```javascript
db.clientes.find({ "endereco.estado": "SP" }).explain("executionStats").executionStats
```

E em campos que armazenam arrays:

```javascript
db.produtos.createIndex({ tags: 1 })
```

```javascript
db.produtos.find({ tags: "usb" }).explain("executionStats").executionStats
```

Quando um índice é criado sobre um array, o MongoDB cria uma entrada no índice para **cada valor** do array. Esse tipo de índice é chamado de **multikey**. Por isso, `totalKeysExamined` pode ser diferente de `nReturned`.

Arrays e campos comuns podem ser combinados em um índice composto:

```javascript
db.produtos.find({ tags: "gamer", categoria: "monitores" })
```

```javascript
db.produtos.createIndex({ tags: 1, categoria: 1 })
```

Restrição importante: um índice composto pode ter **no máximo um campo array**.

---

### 7. Índice único

Um índice único, além de acelerar buscas, impede valores duplicados no campo.

```javascript
db.clientes.createIndex({ email: 1 }, { unique: true })
```

Tentativa de inserir um email repetido:

```javascript
db.clientes.insertOne({
  nome: "Cliente Duplicado",
  email: "cliente1@email.com",
  endereco: { cidade: "Santos", estado: "SP" }
})
```

O MongoDB retorna um erro de chave duplicada (`E11000 duplicate key error`).

Em bancos NoSQL, onde nem sempre há restrições como em bancos relacionais, o índice único é uma forma de transformar uma regra de negócio em uma **regra de integridade** garantida pelo próprio banco.

> O índice único só pode ser criado se a coleção ainda não tiver valores duplicados no campo.

### 8. Gerenciando índices

Listar os índices de uma coleção:

```javascript
db.produtos.getIndexes()
```

Cada índice tem um nome, gerado a partir dos campos e da ordem. Exemplos: `categoria_1`, `categoria_1_preco_-1`.

Remover um índice pelo nome:

```javascript
db.produtos.dropIndex("categoria_1_preco_-1")
```

Remover um índice pela sua definição:

```javascript
db.produtos.dropIndex({ preco: -1, categoria: 1 })
```

Remover todos os índices, mantendo apenas `_id`:

```javascript
db.produtos.dropIndexes()
```

Quando houver vários índices que podem atender a mesma consulta, o MongoDB escolhe um deles. Para comparar índices de forma justa, remova os que não estão sendo testados ou use `hint()`.

### 9. Custos dos índices

Índices melhoram consultas, mas não são gratuitos.

Eles podem gerar custos como:

- maior uso de armazenamento;
- maior custo em inserções;
- maior custo em atualizações;
- necessidade de manutenção;
- risco de criar índices que não são usados.

#### Medindo o custo de escrita

A cada inserção, o MongoDB precisa atualizar **todos** os índices da coleção. Esse custo pode ser medido.

Remova os índices e meça o tempo para inserir 10.000 produtos de teste:

```javascript
db.produtos.dropIndexes()

let lote = []
for (let i = 1; i <= 10000; i++) {
  lote.push({
    codigo: "T" + i,
    categoria: sortear(categorias),
    marca: sortear(marcas),
    preco: Math.round(Math.random() * 4000 + 20),
    tags: [sortear(tags), sortear(tags)],
    cadastradoEm: new Date(),
    teste: true
  })
}

let inicioInsercao = Date.now()
db.produtos.insertMany(lote)
print("Inserção sem índices: " + (Date.now() - inicioInsercao) + " ms")

db.produtos.deleteMany({ teste: true })
```

Agora crie vários índices e repita a mesma inserção:

```javascript
db.produtos.createIndex({ categoria: 1, preco: -1 })
db.produtos.createIndex({ marca: 1, ativo: 1 })
db.produtos.createIndex({ cadastradoEm: 1 })
db.produtos.createIndex({ tags: 1 })

inicioInsercao = Date.now()
db.produtos.insertMany(lote)
print("Inserção com índices: " + (Date.now() - inicioInsercao) + " ms")

db.produtos.deleteMany({ teste: true })
```

O tempo com índices tende a ser maior. Por isso, índices devem ser criados com base em consultas reais ou esperadas, não apenas por intuição.

Algumas boas práticas importantes:

- criar índices para consultas frequentes;
- observar filtros e ordenações usados em conjunto;
- evitar criar índices para todos os campos;
- revisar índices que não são utilizados;
- usar `explain()` para validar hipóteses;
- considerar a seletividade dos campos;
- alinhar os índices à modelagem dos documentos.

### 11. Exemplo final: ganho de tempo com índice

Para que a diferença de tempo fique evidente, são necessárias duas condições:

- uma coleção grande;
- uma consulta seletiva, isto é, que retorna poucos documentos em relação ao total.

Criando uma coleção de eventos com 500.000 documentos, inseridos em lotes de 10.000:

```javascript
db.eventos.drop()

const tiposEvento = ["login", "logout", "compra", "visualizacao", "erro"]

for (let numeroLote = 0; numeroLote < 50; numeroLote++) {
  const eventos = []

  for (let j = 1; j <= 10000; j++) {
    const n = numeroLote * 10000 + j

    eventos.push({
      protocolo: "EVT" + n,
      usuarioId: Math.floor(Math.random() * 20000) + 1,
      tipo: sortear(tiposEvento),
      valor: Math.round(Math.random() * 1000),
      criadoEm: new Date()
    })
  }

  db.eventos.insertMany(eventos)
}

db.eventos.countDocuments()
```

A inserção pode levar alguns segundos. Inserir em lotes evita montar um array com 500.000 documentos de uma só vez na memória do `mongosh`.

#### Medindo o tempo

Uma única medição de tempo pode ser afetada por outros processos da máquina. É melhor executar a consulta algumas vezes e calcular a média.

A função abaixo recebe a consulta **como uma função** (`() => db.colecao.find(...)`), porque um cursor só pode ser percorrido uma vez e precisa ser criado novamente a cada execução:

```javascript
function tempoMedio(gerarConsulta, vezes) {
  let total = 0

  for (let i = 0; i < vezes; i++) {
    const inicio = Date.now()
    gerarConsulta().toArray()
    total += Date.now() - inicio
  }

  return Math.round(total / vezes)
}
```

Consulta por um protocolo específico, sem índice:

```javascript
db.eventos.find({ protocolo: "EVT432100" }).explain("executionStats").executionStats
```

```javascript
tempoMedio(() => db.eventos.find({ protocolo: "EVT432100" }), 3)
```

Criando o índice:

```javascript
db.eventos.createIndex({ protocolo: 1 }, { unique: true })
```

Repetindo a análise:

```javascript
db.eventos.find({ protocolo: "EVT432100" }).explain("executionStats").executionStats
```

```javascript
tempoMedio(() => db.eventos.find({ protocolo: "EVT432100" }), 3)
```

Resultado esperado:

| Métrica | Sem índice | Com índice |
|---------|-----------|------------|
| Estágio | `COLLSCAN` | `IXSCAN` + `FETCH` |
| `totalDocsExamined` | 500000 | 1 |
| `nReturned` | 1 | 1 |
| Tempo | dezenas a centenas de ms | próximo de 0 ms |

Os valores exatos de tempo variam conforme a máquina, mas a diferença deve ser clara: sem índice, o MongoDB lê toda a coleção para encontrar um único documento; com índice, vai direto a ele.

#### Registrando as medições

Para comparar várias consultas, é útil guardar os resultados em uma coleção, como visto na aula 2:

```javascript
const stats = db.eventos.find({ protocolo: "EVT432100" }).explain("executionStats").executionStats

db.medicoes_exemplo.insertOne({
  consulta: "evento por protocolo",
  fase: "com índice",
  nReturned: stats.nReturned,
  totalDocsExamined: stats.totalDocsExamined,
  totalKeysExamined: stats.totalKeysExamined,
  tempoMedioMs: tempoMedio(() => db.eventos.find({ protocolo: "EVT432100" }), 3),
  registradoEm: new Date()
})

db.medicoes_exemplo.find()
```

#### Discussão

Compare com o exemplo da etapa 3:

> Por que o índice em `categoria` quase não alterou o tempo, enquanto o índice em `protocolo` reduziu drasticamente?

A resposta está na seletividade e no volume: `protocolo` é único para cada documento em uma coleção grande, enquanto `categoria` divide uma coleção pequena em apenas cinco grupos.
