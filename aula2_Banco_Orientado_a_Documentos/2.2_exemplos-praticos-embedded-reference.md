# 2.2 Exemplos práticos: embedded e reference

Este material apresenta exemplos práticos de modelagem orientada a documentos usando MongoDB. O foco é comparar duas estratégias comuns em bancos NoSQL: documentos embutidos (*embedded*) e documentos referenciados (*reference*).


---

## 1. Documento embutido

No modelo embutido, dados relacionados ficam dentro do mesmo documento. Essa abordagem costuma ser útil quando as informações são acessadas juntas com frequência.

### Exemplo: cliente com endereço embutido

```javascript
use loja

db.clientes.insertOne({
  nome: "Ana Souza",
  email: "ana@email.com",
  telefone: "11999990000",
  endereco: {
    rua: "Rua das Flores",
    numero: 120,
    cidade: "São Paulo",
    estado: "SP",
    cep: "01000-000"
  }
})
```

Consulta do cliente com o endereço:

```javascript
db.clientes.findOne({ email: "ana@email.com" })
```

Consulta por um campo interno do endereço:

```javascript
db.clientes.find({ "endereco.cidade": "São Paulo" })
```

### Quando faz sentido usar embedded?

- Quando os dados relacionados pertencem naturalmente ao documento principal.
- Quando a consulta normalmente precisa trazer tudo junto.
- Quando o dado embutido não é compartilhado por muitos documentos.

---

## 2. Documento com lista embutida

Também é comum embutir listas quando os itens fazem parte do mesmo contexto.

### Exemplo: pedido com itens embutidos

```javascript
db.pedidos.insertOne({
  cliente: "Ana Souza",
  data: new Date(),
  status: "aberto",
  itens: [
    {
      produto: "Teclado",
      quantidade: 1,
      precoUnitario: 120.00
    },
    {
      produto: "Mouse",
      quantidade: 2,
      precoUnitario: 60.00
    }
  ]
})
```

Consulta de pedidos que possuem determinado produto:

```javascript
db.pedidos.find({ "itens.produto": "Mouse" })
```

Atualização do status do pedido:

```javascript
db.pedidos.updateOne(
  { cliente: "Ana Souza", status: "aberto" },
  { $set: { status: "finalizado" } }
)
```

## 3. Documento referenciado

No modelo por referência, os dados ficam em coleções separadas, e um documento guarda o identificador de outro. Essa abordagem costuma ser útil quando a informação relacionada é reutilizada ou atualizada separadamente.

### Exemplo: cliente e pedidos separados

```javascript
db.clientes.insertOne({
  _id: ObjectId("650000000000000000000001"),
  nome: "Bruno Lima",
  email: "bruno@email.com"
})

db.pedidos.insertOne({
  clienteId: ObjectId("650000000000000000000001"),
  data: new Date(),
  status: "aberto",
  valorTotal: 250.00
})
```

Consulta dos pedidos de um cliente:

```javascript
db.pedidos.find({
  clienteId: ObjectId("650000000000000000000001")
})
```

Consulta do cliente:

```javascript
db.clientes.findOne({
  _id: ObjectId("650000000000000000000001")
})
```

### Quando faz sentido usar reference?

- Quando o dado relacionado é compartilhado por vários documentos.
- Quando a informação relacionada muda com frequência.
- Quando o documento embutido ficaria muito grande.
- Quando há necessidade de consultar as entidades separadamente.

## 4. Comparando as duas abordagens

### Embedded

```javascript
db.alunos.insertOne({
  nome: "Carla Mendes",
  curso: "Banco de Dados",
  matricula: "2026001",
  disciplinas: [
    { nome: "Banco de Dados Não Relacional", semestre: 3, situacao: "cursando" },
    { nome: "Modelagem de Dados", semestre: 2, situacao: "aprovada" }
  ]
})
```

### Reference

```javascript
db.alunos.insertOne({
  _id: ObjectId("650000000000000000000010"),
  nome: "Carla Mendes",
  curso: "Banco de Dados",
  matricula: "2026001"
})

db.disciplinas.insertMany([
  {
    alunoId: ObjectId("650000000000000000000010"),
    nome: "Banco de Dados Não Relacional",
    semestre: 3,
    situacao: "cursando"
  },
  {
    alunoId: ObjectId("650000000000000000000010"),
    nome: "Modelagem de Dados",
    semestre: 2,
    situacao: "aprovada"
  }
])
```

## 5. Exercícios

1. Crie uma coleção `usuarios` em que cada usuário tenha um endereço embutido.
2. Crie uma coleção `pedidos` em que cada pedido tenha uma lista de itens embutidos.
3. Modele uma situação em que `produtos` e `fornecedores` fiquem em coleções separadas, usando referência.
4. Explique qual abordagem você usaria para armazenar comentários de uma postagem: embedded ou reference.
5. Explique qual abordagem você usaria para armazenar dados de departamentos e funcionários de uma empresa.

## 6. Discussão

Para cada exercício, avalie:

- os dados são consultados juntos ou separados?
- o dado relacionado é compartilhado por vários documentos?
- a informação muda com frequência?
- o documento pode crescer demais com o tempo?
- a modelagem facilita as consultas mais importantes da aplicação?
